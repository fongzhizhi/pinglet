# Pinglet 使用说明

> 对应版本：v1.3.0。以下行为以 Windows 桌面端为准。

## 看板状态

看板收敛为四种状态，文案统一为三字：

| 看板状态 | 判定依据 | 说明 |
| --- | --- | --- |
| 待处理 | `waiting` / `blocked` | 等待用户输入或权限确认，红色置顶 |
| 已中断 | 进程已退出，或 `failed` / `crashed` / `stopped` | 异常退出、报错崩溃或被手动强行停止 |
| 进行中 | `busy` / `shell` / `working` / `starting` / `running` / `resuming` / `adopted` | AI 正在思考或执行命令；未知状态且进程存活时也按此兜底 |
| 已完成 | `idle` / `done` | 上一轮任务结束，等待下一个 Prompt |

- 正常退出会删除会话文件，残留的 `alive = false` 记录归为「已中断」。
- 排序：待处理 > 已中断 > 进行中 > 已完成。待处理 / 进行中按开始时间升序（等得久的在前），已中断 / 已完成按最近更新倒序。
- 未知状态不显示「未知」，进程存活时兜底为「进行中」；解析失败或字段缺失不会导致崩溃。
- 标题优先级：`nameSource = "hook"` 的 `name`（用户标题）> transcript 中最后一条 `custom-title` > 最后一条 `ai-title` > `nameSource = "derived"` 时用目录名 > 内部名 / 「未命名会话」。不再把 `demo-alpha-3f` 这类内部 slug 当作标题展示。

## 界面

### 顶栏

- 左侧为极简 logo（三层图形静态映射 待处理 / 已中断 / 进行中，未激活图层保留状态色但更淡）；悬停约 1.5 秒可查看数据刷新状态。
- 汇总胶囊按 待处理 > 已中断 > 进行中 的顺序显示非零数量（如 `1 待处理`、`2 已中断`、`3 进行中`，文字跟随对应状态色）；没有进行中且无异常会话时只显示 logo。
- 右侧按钮：图钉、设置、关闭。窗口始终置顶，图钉只切换顶栏是否可拖动；按钮文案表示点击后进入的模式——拖动模式下显示「固定模式」，固定模式下显示「拖动模式」；图标亮 = 固定且不可拖动。
- 关闭按钮随设置变化：开启「关闭时最小化到托盘」时显示最小化图标与「最小化」文案，关闭时显示 ✕ 与「退出」文案。

### 会话行

- 两行布局：第一行 `状态灯 + 状态字 + 会话标题 + 时间状态`；第二行 `目录名 + vs-code / cli 环境标签`，整体右对齐。
- 目录名在前，入口标签在后，两者同为标签样式。标题超出省略，目录只显示文件夹名。
- 标签文字使用实色。目录按完整路径哈希稳定分配低饱和色板槽位——同一目录同色、不同目录尽量不同色；同时可见目录超过 8 个时循环复用色板。
- 入口标签固定三色：`vs-code` 蓝、`cli` 紫、其他中性色。
- 色板随亮 / 暗主题切换，饱和度低于四态语义色，避免压过状态信息。

### 悬浮提示

- 悬停约 1.5 秒后弹出，展示完整路径、完整标题、状态、入口、进程与最后更新时间。
- 标题与内部名不同时补充内部名，并展示会话 ID，便于区分同目录多会话。
- 底部提示「双击激活会话窗口」；双击会话行后立即收起，不再弹出。
- 不读取消息正文，因此不展示 Prompt 内容。

### 双击 / Enter 激活

仅入口为 `vs-code` / `cli` 的会话支持激活，其他入口仅行内闪烁并提示不支持。

- VSCode 会话会打开目录并主动将已存在的 VSCode 窗口切到前台；启动时会剔除开发环境继承的 `ELECTRON_RUN_AS_NODE`（否则 `Code.exe` 会被 Electron 当作 Node 运行）。
- CLI 会话先沿进程父链识别是否运行在 VSCode 集成终端中——是则激活对应的 VSCode 窗口，否则按启动目录或终端标题聚焦已有 Git Bash 窗口。
- 都匹配不到时行内闪烁并在底部提示，不会新开窗口。底部提示保留约 2 秒。无右键菜单。

### 心跳

- 悬停顶栏 logo 约 1.5 秒后弹出提示：第一行为品牌名 `Pinglet`，第二行为心跳圆点 + `刷新于 HH:mm:ss`。
- 绿色正常、黄色 > 5 秒未更新、红色 > 15 秒未更新；尚无数据时显示「尚未刷新」。

## 主题与设置

设置只写入本机 WebView 的 `localStorage`（`pinglet.settings.v1`），不会写 Claude 配置，也不为「主题」增加 Rust command。根节点 `data-theme="dark" | "light"` 切换语义 CSS 变量：

| 状态 | 暗色 | 亮色 |
| --- | --- | --- |
| 待处理 | `#FF4D4F` | `#D93025` |
| 已中断 | `#FAAD14` | `#D97706` |
| 进行中 | `#2ED573` | `#059669` |
| 已完成 | `#787878` | `#9CA3AF` |

- 暗色背景 `#18181B`，亮色背景 `#FFFFFF`；设置面板与 Tooltip 为不透明纯色，主面板背景可通过透明度滑块调整；均不使用 `backdrop-filter`。
- 默认配置：暗色主题、标准字号、面板透明度 0%（完全不透明）、开启呼吸灯 / 音效 / 窗口抖动、关闭「点击关闭时最小化到托盘」、拖动模式、关闭鼠标穿透、关闭开机自启、快捷键 `Alt+Shift+P`。
- 字号三档：小 `13px` / 标准 `14px` / 大 `15px`。通过 `--font-size-base` 联动 Logo、图钉 / 设置 / 关闭图标、状态圆点、心跳点、开关与按钮尺寸，切换后自动按内容重算窗口高度。
- 透明度：设置面板提供 0%–70% 滑块（步进 5%，默认 0%），数值越大面板背景越透；文字、图标与状态色保持不透明。设置面板本身不透明，避免调节时文字互相干扰。
- 窗口宽度、高度与字号保存在本机 `localStorage`（窗口尺寸键为 `pinglet.window.v1`）。
- 「恢复默认」会清空全部本地设置、恢复默认系统项，把窗口宽度重置为 `280px`，字号 / 主题 / 透明度 / 提醒恢复默认，并刷新页面。

### 提醒

- 提醒模式多选：呼吸灯 / 音效 / 窗口抖动；选择「无」会清空其他三项。
- 勾选任一生效项时立即演示对应效果（呼吸灯闪烁三次，约 3.3 秒；抖动持续约 0.6 秒、来回三次）。
- 提醒触发分两档：
  - 待处理 / 已中断的状态突变触发强提醒——呼吸灯按对应状态色闪烁三次，音效响一次，窗口抖动来回三次。
  - 进行中 → 已完成触发完成提醒——呼吸灯用进行中绿色闪烁一次，音效响一次，窗口抖动一次（约 0.3 秒）。
- 音效与抖动均受各自开关控制。启动时已存在的会话状态不补闪。

### 鼠标穿透

- 在设置面板中开启后，等面板关闭才真正生效，避免面板立刻失去点击能力。生效后窗口不接收鼠标事件，点击会落到下方窗口。
- 按全局快捷键（默认 `Alt+Shift+P`）或点击托盘左键，会先关闭穿透再显示 / 聚焦窗口；也可右键托盘图标 →「鼠标穿透」取消勾选。
- 设置面板、托盘勾选与快捷键切换三方同步。

### 开机自启与快捷键

- 开机自启与关闭行为通过 Tauri 插件与 Rust command 实现。
- 全局快捷键默认 `Alt+Shift+P`，可聚焦输入框后重新录制，Backspace 清除。

### 关于

- 关于区显示 `Pinglet v1.3.0` 与开发者信息，底部提供「恢复默认」与「退出应用」。
- 恢复默认会同时重置关闭行为、鼠标穿透、开机自启与快捷键（窗口始终保持置顶）。
- 设置面板顶部提供「← 返回」按钮，点击即可收起面板，与再次点击齿轮等效。

## 窗口行为

- 默认宽度 `280px`（即最小宽度），可拖拽调整：宽度 `280–600px`，高度 `200–800px`。四边 5px、四角 10px 透明热区，按下后交给系统执行缩放拖拽。禁用系统最大化，双击顶栏只会开始拖动，不会把窗口放大。
- 高度随内容自适应：内容变多时撑开窗口，内容减少时自动收缩；未拖拽过时默认增长上限为 `320px`（标准字号约 5 行会话），用户拖拽过的高度作为上限。超过上限时列表内部滚动，而不是继续撑高窗口。自动调整遇到用户拖拽后 500ms 内暂停，避免与系统拖拽互相拉扯。
- 宽度、高度偏好持久化到 `localStorage`；启动恢复宽度后若窗口越出工作区，会自动向左上推回可见范围。
- 窗口隐藏或最小化期间暂停轮询与心跳刷新，恢复可见后立即刷新一次。
- 滚动条默认隐藏，仅在列表 hover 或实际滚动时显示 4px 细滚动条。
- 无边框、圆角、跳过任务栏；窗口始终置顶，点击非面板区域不会把它压到其他窗口后面。拖动模式可拖动顶栏，固定模式锁定位置。窗口透明用于圆角与面板背景透明度；默认面板背景不透明。
- 拖动到屏幕边缘约 10px 内时自动吸附；吸附后需向外拖动约 24px 才解除，避免小步拖动被反复拉回边缘。

## 托盘菜单

右键托盘图标提供四项：

- **显示**：勾选表示窗口当前可见，点击切换显隐。
- **鼠标穿透**：勾选表示穿透中，点击切换。
- **设置**：显示窗口并打开设置面板，穿透中会先关闭穿透。
- **退出**：退出应用。

关闭到托盘后可通过托盘菜单或全局快捷键重新显示。穿透开启时，全局快捷键与托盘左键优先恢复可点击状态（关闭穿透并显示 / 聚焦窗口）。设置中关闭「最小化到托盘」后，点击 X 会直接退出应用。

## 常见问题

### VS Code 扩展启动的会话不显示

Pinglet 只能发现写入 `%USERPROFILE%\.claude\sessions\*.json` 的会话。部分版本的 Claude Code VS Code 扩展以非交互方式启动底层 CLI，不写这份注册文件，因此这些会话不会出现在看板上——这是数据源缺失，不是 Pinglet 读取失败。

- 优先把 Claude Code VS Code 扩展升级到最新版，升级后新开的会话会正常写入注册文件。
- 验证方法：插件会话运行时检查 `%USERPROFILE%\.claude\sessions\` 下是否出现对应 `*.json`；没有就说明注册缺失。
- 升级后仍不写入时，可改用 VS Code 集成终端直接运行 `claude`（交互模式）。该方式会正常注册，也能被看板双击激活。

## 已知限制

- Prompt 内容不在 `sessions/*.json` 中；Pinglet 只读取 transcript 的标题记录，不读取消息正文，因此 tooltip 不包含提问内容。
- 尚无任何标题的新会话（`nameSource = "derived"` 且 transcript 中无 `custom-title` / `ai-title`）会回退显示目录名；同目录多个未命名会话的标题会相同，可用 tooltip 里的内部名 / 会话 ID 区分，或通过 session-keeper / `/rename` 设置标题。
- VSCode 会话会按目录名匹配并聚焦已打开该目录的窗口；若目录尚未在 VSCode 中打开，则新开窗口后聚焦。CLI 会话运行在 VSCode 集成终端中时，按会话进程的父链找到所属 VSCode 主进程，再用 cwd 的各级目录名匹配窗口标题；标题匹配不到且该进程只有一个窗口时直接激活，多个窗口且都无法匹配则提示无法定位。
- 其余 CLI 会话先按 Git Bash 的启动目录（`--cd`）匹配，再按 Claude Code 写入的终端标题匹配；终端既不是 VSCode 也不是 Git Bash（如 Windows Terminal）、启动时没有 `--cd` 且标题被其他程序覆盖、或窗口内手动 `cd` 后标题也被覆盖时，会提示无法激活，不会新开窗口。
- 鼠标穿透开启后窗口不接收鼠标事件，需通过全局快捷键、托盘左键或托盘菜单「鼠标穿透」恢复；若全局快捷键注册失败且托盘不可用，将无法从窗口内部关闭穿透。
- 托盘、开机自启、全局快捷键、边缘吸附、鼠标穿透等系统集成需在真实桌面环境中验收。
- 当前安装包未做代码签名，首次运行可能触发 Windows SmartScreen 提示。
