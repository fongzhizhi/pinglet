# Pinglet v1.4 计划：托盘状态、自动主题与告警通知

> NOTE: 本文是 2026-11-10 的设计稿，功能尚未实现。实现时若与代码或[使用说明](../usage.md)不一致，以代码与使用说明为准。
>
> 评估环境：本机 Windows 10（19045）+ Node 24，但未安装 Rust / Tauri 工具链，Rust 侧结论需在真机或 CI 的 Windows runner 上验证。本文中的“建议”“预期”均不是实测数据。
>
> 2026-11-10 更新：已确认产品决策，并把单实例保护、免打扰、窗口位置记忆、托盘 tooltip、汇总区/心跳差量更新统一纳入本次实现范围。

## 一、背景与目标

当前 Pinglet 的状态展示集中在主窗口内：窗口隐藏到托盘后，用户只能靠声音或再次打开窗口感知变化；主题只能手动切换。本次计划统一实现：

1. **托盘图标状态化**：警告类会话出现时闪烁，进行中时显示绿色高亮环，空闲时保持静默。
2. **自动主题**：根据窗口下方背景明暗自动切换暗色 / 亮色主题，识别不到时保持当前主题。
3. **告警弹窗**：警告出现时在屏幕右下角弹出类 QQ / 有度的消息提示，作为闪烁之外的增强通道。
4. **配套改进**：单实例保护、免打扰模式、窗口位置记忆、托盘 tooltip 汇总、汇总区与心跳差量更新。

非目标：

- 不引入网络请求、不调用 Claude API、不写入 `~/.claude`，继续保持只读、离线。
- 不改变四态模型、排序规则与现有提醒优先级。
- 不新增「未知」状态。

## 二、现状与约束

| 位置 | 现状 |
| --- | --- |
| 托盘图标 | `create_tray` 使用 `default_window_icon`，创建后不再更新（`src-tauri/src/lib.rs`） |
| 托盘菜单 | 显示 / 鼠标穿透 / 设置 / 退出，勾选状态与前端同步 |
| 汇总数据 | 前端每轮轮询后计算 `blockedCount` / `interruptedCount` / `workingCount`，并驱动 logo、胶囊与提醒（`src/main.ts`） |
| 轮询 | 可见时 `REFRESH_INTERVAL_MS`（2 秒）；`document.visibilityState === "hidden"` 时直接跳过 |
| 提醒 | `detectStateChange` 每轮最多产生一个事件；启动首轮已有会话不补闪；异常优先于「进行中 → 已完成」 |
| 主题 | `ThemeMode = "dark" \| "light"`，持久化在 `pinglet.settings.v1`，`applyTheme` 只改根节点 `data-theme` |
| 设置面板 | 主题为两段式选择（暗色 / 亮色） |
| 窗口尺寸 | 持久化在 `pinglet.window.v1`，只记宽高；启动时 Rust 固定定位到主屏右上角 |
| 单实例 | 未做限制，重复启动会出现多个托盘图标、重复轮询与重复提醒 |

### 关键约束：隐藏窗口时的轮询可靠性

当前隐藏时主动跳过轮询，只是第一层原因。即使删掉 `visibilityState` 判断，WebView2 / Chromium 对隐藏页面还有**后台定时器节流**：隐藏一段时间后 `setInterval` 可能被降频到每秒甚至每分钟一次。因此「隐藏时低频轮询」必须同时解决节流问题，否则托盘状态和弹窗都不可靠。

可选做法：

1. 在 `tauri.conf.json` 的窗口配置中设置 `backgroundThrottling: "disabled"`（Tauri 2.12 提供该配置，实现前先用 schema 校验字段名与取值）；或追加 WebView2 参数 `--disable-background-timer-throttling`。
2. 把轮询下沉到 Rust：后台线程 / 异步任务每 5 秒调用一次会话采集逻辑并更新托盘、触发通知，前端只负责渲染。该方案不受 WebView 节流影响，但需要把 `list_sessions` 的采集部分抽成可复用函数。

建议先采用方案 1（改动小），真机验证隐藏 10 分钟以上定时器仍正常；若不可靠再切到方案 2。

### 隐藏时的轮询频率

- 可见时保持 2 秒。
- 隐藏时建议 5 秒。
- 心跳动画只在可见时更新，保持不变。

## 三、方案 A：托盘图标状态化

### 3.1 交互状态机

| 汇总状态 | 条件 | 托盘表现 | 优先级 |
| --- | --- | --- | --- |
| `alert` | 待处理 > 0 或已中断 > 0 | 警示色图标；窗口隐藏且未读时持续闪烁（约 600–800 ms 切换一次） | 最高 |
| `working` | 无警告且进行中 > 0 | 基础图标 + 绿色圆环（常亮） | 中 |
| `idle` | 其余情况（含无会话） | 基础图标，静默 | 低 |

已确认语义：

- **「警告」同时包含待处理与已中断**，任一计数大于 0 即进入 `alert`。
- **已读语义**：点击托盘 / 全局快捷键 / 通知唤起主窗口后，视为已读——停止闪烁，但保留常亮警示色；警告计数归零后才恢复普通图标。
- **未读语义**：窗口隐藏期间出现新的警告状态变化时，重新开始闪烁。
- **免打扰开启时**：不闪烁，只显示常亮警示色；进行中绿环与列表状态不受影响。

### 3.2 技术实现

1. 新增命令 `set_tray_state`，载荷包含 `status`（`idle` / `working` / `alert`）、三类计数与 `blink` 标志。前端只在汇总状态、计数或 `blink` 变化时调用，不随每轮轮询重复调用。
2. 新增命令 `acknowledge_tray_alert`：主窗口变为可见时由前端调用，清除未读标志（停止闪烁）。
3. `AppState` 增加原子状态（如 `tray_state: Mutex<TrayState>`）；Rust 侧启动一个低频后台线程：
   - 非 `alert` 或 `blink = false` 时直接睡眠，不做图标更新。
   - `blink = true` 时每 600–800 ms 切换一次「亮 / 暗」两个警示图标。
   - 睡眠粒度建议 200–300 ms，用于及时响应状态切换。
4. 动态图标通过 `app.tray_by_id(TRAY_ID)` 取得托盘句柄后调用 `set_icon`。Tauri 2 的托盘支持运行时更新；若后台线程调用受限，改用 `app.run_on_main_thread(...)`。
5. 图标生成方式（二选一）：
   - **推荐**：内存合成。取 `default_window_icon()` 的 RGBA，将内容缩到约 80% 画布居中，再画 2px 圆环，用 `Image::new_owned(rgba, w, h)` 生成变体；不新增素材文件，随源图标自动保持一致。
   - 预渲染 PNG：新增 `assets/tray-*.png`，用 `Image::from_bytes` 加载；需要 `image-png` feature。视觉更可控，但多一份素材维护成本。
6. 状态优先级与前端汇总一致；某次轮询同时出现多种状态时取最高优先级。
7. 圆环还是角标：先用圆环实现，真机 16px 下对比后再定；若圆环不可辨识，退回右下角彩色角标。

### 3.3 托盘 tooltip 汇总

- 与 `set_tray_state` 一起更新，仅在计数或状态变化时调用 `set_tooltip`。
- 文案示例：
  - 有警告：`Pinglet · 1 待处理 · 1 已中断 · 2 进行中`
  - 无警告：`Pinglet · 2 进行中`
  - 无会话：`Pinglet`
- Windows 托盘 tooltip 长度有限，保持单行、简短；不展示目录名或任何会话内容。
- tooltip 只作为悬停补充，不替代图标状态。

### 3.4 性能

- 闪烁约每秒 1–2 次 `Shell_NotifyIcon` 调用，CPU 影响基本为 0。
- 非 `alert` 或已读状态零图标更新。
- 隐藏时轮询 5 秒一轮，`list_sessions` 只读取会话 JSON 并按 PID 定向刷新进程信息，预期单核占用远低于 1%；需要在真机任务管理器中确认。
- 不涉及磁盘写入与网络。

### 3.5 风险与设计注意

- **16px 可见性**：Windows 托盘逻辑尺寸为 16×16，圆环只有约 1–2px。建议真机在 100% / 125% / 150% 缩放下验收；若不可见，改用角标。
- **持续闪烁**：已通过「打开面板即停止」的已读语义控制时长；免打扰开启时完全不闪。
- **换图标闪动**：部分 Windows 版本切换托盘图标会有轻微闪动，600 ms 以上间隔通常可接受。
- **托盘溢出区**：Windows 可能把图标收进溢出区，这是系统行为，应用无法强制常显。
- **多实例**：由单实例保护解决（见 6.1）。

### 3.6 验收

- 三种状态切换正确，优先级正确。
- 窗口隐藏时新出现的警告能触发闪烁；打开面板后停止闪烁并保留警示色；警告消失后恢复普通图标。
- 免打扰开启时不闪烁，但警示色、绿环、tooltip 计数仍正确。
- 100% / 125% / 150% 缩放下圆环与闪烁可辨识。
- 空闲时任务管理器 CPU 无明显上升。

## 四、方案 B：自动主题

### 4.1 交互

- 主题选项扩展为「暗色 / 亮色 / 自动」，默认仍为暗色。
- 只有用户选择「自动」时才根据背景明暗切换；手动选择暗色 / 亮色时立即覆盖。
- 判定规则（建议值，真机调参）：

| 下方背景亮度 | 生效主题 |
| --- | --- |
| ≥ 0.65 | 暗色 |
| ≤ 0.35 | 亮色 |
| 0.35–0.65 或采样失败 | 保持当前主题 |

- 防抖：
  - 窗口移动 / 缩放结束后延迟 300–500 ms 再采样。
  - 连续两次采样结果一致才切换。
  - 可加最小切换间隔（如 10 秒），避免视频、动画背景导致主题来回跳。
- 窗口隐藏时跳过采样。
- 阈值与采样位置在真机测试时再调整。

### 4.2 采样实现

- 仅 Windows：在 `windows-sys` 现有依赖上增加 `Win32_Graphics_Gdi` feature。
- 取窗口物理坐标（`outer_position` / `outer_size`），在窗口底部下方约 4–8px 处横向取 8–16 个像素，夹到当前显示器工作区内。
- 使用 `GetDC(NULL)` + `GetPixel`（或 `BitBlt` 到 1×N 位图）读取像素，计算相对亮度：

  `L = 0.2126 * R/255 + 0.7152 * G/255 + 0.0722 * B/255`

- 取中位数比平均值更抗小面积文字、图标干扰。
- `GetPixel` 返回 `CLR_INVALID` 或采样区域越界时视为「识别不到」。
- 新增命令（如 `sample_backdrop_luminance`）返回 `Option<f32>`；前端在轮询节拍中每 8–10 秒调用一次，并在窗口移动后防抖调用。

### 4.3 设置模型

- `ThemeMode` 增加 `"auto"`；`parseSettings` 接受该值，旧数据保持兼容。
- 内部区分「用户选择」与「实际生效主题」：持久化 `theme = auto`，`applyTheme` 使用解析后的 `effectiveTheme`。
- 设置面板增加第三段「自动」；`docs/usage.md` 同步更新。
- CSS 无需新增变量，继续复用 `:root[data-theme="light"]`。

### 4.4 性能

- 每 10 秒读取十几个屏幕像素，耗时微秒级，可忽略。
- 只有生效主题变化时才改根节点属性，小窗口重绘一次。
- 不做持续截屏，不占用额外内存。

### 4.5 风险与边界

- 窗口下方可能是任务栏或另一个窗口；这通常正是期望的对比背景，但任务栏颜色会影响判断。
- 独占全屏 / DRM 内容可能读不到或恒为黑色，按「识别不到」处理。
- 动态视频、渐变壁纸可能造成抖动，依赖防抖与最小切换间隔。
- 多显示器下必须夹到窗口所在显示器的工作区，避免采到屏幕外。
- 隐私：只在内存中读取少量像素，不落盘、不联网。

### 4.6 验收

- 在浅色、深色、灰色背景下分别验证切换与保持。
- 窗口跨显示器移动、贴近任务栏、最小化再恢复时行为正确。
- 动态背景连续观察 1 分钟不出现频繁切换。
- 采样失败时主题保持不变。

## 五、方案 C：告警弹窗

### 5.1 现有提醒与可复用点

`detectStateChange` 已经能按「异常优先、启动首轮不补发、同轮取最高优先级」产生提醒事件，可直接作为弹窗触发源，避免再写一套状态判断。

### 5.2 已确认的触发规则

- **仅当主窗口隐藏且出现新增异常时触发**；窗口可见时依赖现有呼吸灯 / 音效 / 抖动与列表本身。
- 只在**状态突变**时触发：启动首轮已有会话不补发，与现有提醒规则一致。
- 免打扰开启时不弹窗。
- 同一次轮询最多一条，聚合为汇总文案，例如：
  - 标题：`Pinglet · 2 个会话待处理`
  - 正文：`api-server 等待确认；web-client 已中断`
- 冷却时间建议 30–60 秒，避免多条会话连续变化时轰炸。
- 点击弹窗：唤起主窗口，并视为已读（停止托盘闪烁）。
- 设置面板新增「系统通知」开关，默认开启；用户可随时关闭。

### 5.3 方案对比与路线

| 方案 | 效果 | 成本 | 主要限制 |
| --- | --- | --- | --- |
| A. Windows 原生 Toast（`tauri-plugin-notification`） | 右下角系统通知，最接近 QQ 消息提示；进入操作中心 | 低（约 0.5 天） | 依赖 AppUserModelID / 开始菜单快捷方式；受专注助手、按应用通知开关影响；样式不可定制；桌面端点击回调有限 |
| B. 自绘右下角弹窗窗口 | 样式与 Pinglet 一致；可点击打开面板或定位会话；便携版同样可用 | 中（约 1.5–2.5 天） | 多一个 WebView2 窗口（约几十 MB 内存）；需处理多显示器、DPI、焦点、生命周期 |
| C. 仅应用内提醒 | 现有呼吸灯 / 音效 / 抖动 | 已有 | 窗口隐藏时看不到 |

推荐路线：

1. 先接入原生 Toast，满足「像 QQ 消息提示」的主要诉求，成本最低。
2. 真机验证 NSIS 安装版、`tauri dev`、便携版三种形态；若便携版不显示或点击体验不可接受，再实现自绘窗口替换。
3. 自绘方案作为后备，不在首轮实现范围内。

> 原生 Toast 在 Windows 上的安装形态限制需真机验证：NSIS 安装版通常可用，`tauri dev` 与便携版可能不显示或归属到通用应用名下。

### 5.4 实现要点

原生 Toast：

- 依赖 `tauri-plugin-notification`，capability 增加 `notification:default`，前端调用 `sendNotification`。
- Windows 权限由系统接管，通常无需运行时申请。
- 开发模式、便携版、NSIS 安装版三种形态都要单独验证。
- 通知内容只使用标题与目录名，不包含 Prompt 或消息正文。

自绘弹窗窗口（后备）：

- 新增窗口 label（如 `toast`）：`decorations: false`、`transparent: true`、`alwaysOnTop: true`、`skipTaskbar: true`、`focus: false`、`resizable: false`、初始 `visible: false`。
- 位置取主窗口所在显示器的工作区右下角（已排除任务栏），留 12–16px 边距；多显示器与 DPI 需单独测。
- 新增 HTML 入口或 `?toast=1` 视图；capability 的 `windows` 列表加入新 label。
- 懒创建 + 复用隐藏，或弹窗结束后销毁，控制 WebView2 内存占用。
- 点击窗口后隐藏弹窗并唤起主窗口。

### 5.5 性能

- 只在状态突变时触发，无持续开销。
- 原生 Toast 不增加常驻内存。
- 自绘窗口会增加一个 WebView2 实例（约几十 MB），CPU 可忽略；需在真机确认内存增量。

### 5.6 验收

- 隐藏窗口时新增警告能触发且只触发一次（受冷却约束）。
- 启动首轮不弹窗；窗口可见时不弹窗。
- 免打扰开启时不弹窗。
- 专注助手开启时原生 Toast 的降级行为符合预期，必要时在文档中说明。
- 点击弹窗能正确唤起主窗口并停止闪烁。
- 连续多条会话变化时不刷屏。

## 六、配套改进（本次一并实现）

### 6.1 单实例保护

- 接入 `tauri-plugin-single-instance`，在 `tauri::Builder::default()` 中**第一个注册**（插件要求先于其他插件初始化）。
- 第二次启动时的回调：关闭鼠标穿透 → 显示 / 还原并聚焦已有主窗口 → 同步托盘「显示」勾选。
- 复用现有 `toggle_main_window` / 显示逻辑，不新增权限。
- 验收：重复双击 exe 只保留一个托盘图标与一个轮询实例；第二次启动会把已有窗口带到前台。

### 6.2 免打扰 / 专注模式

- 设置模型新增 `doNotDisturb: boolean`，默认 `false`，持久化在 `pinglet.settings.v1`，旧数据缺字段时按默认值处理。
- 设置面板在「提醒」区域增加 Switch，文案建议「免打扰」，描述「暂停闪烁、系统通知、音效、抖动与呼吸灯」。
- 开启后的行为：
  - 不触发呼吸灯、音效、窗口抖动、完成提示、系统通知。
  - 托盘不闪烁，只保留常亮警示色；进行中绿环、tooltip 计数与列表状态不变。
  - 设置面板里的「预览提醒」仍可执行一次，便于确认配置（显式操作，不受免打扰限制）。
- 关闭后重新评估当前告警：若仍有未读警告，恢复闪烁；若已读则保持常亮。
- 不做定时自动恢复，保持为纯设置项；后续如需「暂停 30 分钟」可在托盘菜单追加。
- 验收：开启后所有主动提醒静默，但状态展示完整；关闭后行为恢复。

### 6.3 窗口位置记忆

- 推荐使用 `tauri-plugin-window-state`，只启用 `StateFlags::POSITION`，**不要启用 `SIZE`**，避免与现有的内容自适应高度和 `pinglet.window.v1` 冲突。
- 启动时在窗口显示前恢复位置；首次启动或状态文件缺失时保留现有「主屏右上角」逻辑。
- 恢复位置后仍需夹回当前显示器工作区，处理显示器拔插、分辨率变化；可在 Rust 侧新增 clamp，或保留前端 `keepWindowInsideWorkArea` 作为兜底。
- 插件在退出 / 关闭时保存；强制结束进程可能丢失最后一次位置，可接受。
- 备选方案：扩展 `pinglet.window.v1` 记录 `x` / `y`，前端恢复后延迟显示窗口；改动更大，若插件在真机上出现兼容问题再切换。
- 验收：拖动窗口后退出重启，位置与尺寸都恢复；跨显示器、显示器断开后窗口仍在可见区域。

### 6.4 汇总区与心跳差量更新

- 汇总区：当前每 2 秒 `replaceChildren` 重建胶囊。改为先比较计数签名（待处理 / 已中断 / 进行中），只有变化时才重建 DOM；无变化时直接返回。
- 心跳：当前每秒更新 `dataset.level`、`title`、`aria-label` 与 `textContent`。改为：
  - 文案精度改为分钟（`刷新于 HH:MM`），避免每秒必然变化的秒数导致无法差量。
  - 仅在等级或分钟变化时更新 DOM。
  - 评估把 `aria-live` 从每秒变化的心跳移走，或改为非 live 的 `role="img"`，减少读屏器重复播报（与优化待办中的可访问性项合并）。
- 目标：降低 2 秒 / 1 秒节拍下的 DOM 变更、布局抖动与读屏器噪音，视觉与信息量保持不变。
- 验收：DevTools 中 MutationObserver 计数明显下降；界面文案与刷新状态仍正确；读屏不再每秒播报。

## 八、已确认的产品决策

1. 「警告」同时包含待处理与已中断。
2. 闪烁采用已读语义：打开面板即停止闪烁，保留常亮警示色；新警告出现时重新闪烁。
3. Toast 仅对「主窗口隐藏 + 新增异常」生效；免打扰开启时不触发；设置中的「系统通知」开关默认开启。
4. 自动主题的阈值先按本文建议值实现，真机测试时再调整。
5. 托盘高亮先用绿色圆环实现，实机 16px 下对比后再决定是否改为角标。
