## 一、背景与目标

v1.4.0 发布后经过一段时间实际使用，收集到一批体验细节问题。本次只做小幅调整，保持只读、离线与现有状态模型不变。

非目标：

- 不引入网络请求、不调用 Claude API、不写入 `~/.claude`。
- 不改变四态模型、排序规则、提醒优先级与窗口行为。
- 不新增设置项，除非单条讨论中明确需要。

## 二、已确认的优化项

### 2.1 通知弹窗停留时间 3 秒 → 5 秒

**问题**：通知弹窗停留时间偏短，阅读多条内容时来不及看完。

**方案**：

- `src/notification.ts` 的 `AUTO_HIDE_MS` 由 `3000` 改为 `5000`；淡出动画仍按 `LEAVE_ANIMATION_MS` 提前 240ms 触发，逻辑不动。
- `src-tauri/src/lib.rs` 的 `NOTIFICATION_AUTO_HIDE_FALLBACK` 由 5 秒改为 8 秒。兜底计时从显示时刻开始，若保持 5 秒会与前端隐藏几乎同时甚至抢先，截断淡出动画；8 秒保持「停留时长 + 约 3 秒容错」的原有比例（v1.4 早期为「停留 6 秒 + 兜底 8 秒」）。
- 同步文案：`src/settings-panel.ts` 设置项描述、`docs/usage.md`、`README.md`、`CLAUDE.md` 中「3 秒后自动隐藏」的表述改为 5 秒；实现时全局搜索「3 秒」确认无遗漏。

**不做**：不把停留时长做成设置项，固定 5 秒符合补丁版本定位。

### 2.2 Logo 去掉置灰 / 高亮切换，保持常亮

**问题**：顶栏 logo 的置灰 / 高亮切换信息量有限，视觉上反而显得闪烁、不够稳定。

**现状**：三段图形（待处理红 / 已中断橙 / 进行中绿）默认 `opacity: 0.5`，对应状态计数大于 0 时加 `.active` 点亮到 `1`，带 0.3s 过渡。

**方案**：

- `src/styles.css`：删除 `.logo-part` 的 `opacity: 0.5` 与 `transition`，删除 `.logo-part.active` 规则（SVG 默认完全不透明）。
- `src/main.ts`：删除 `renderLogoState` 函数及其调用，删除 `logoPendingElement` / `logoInterruptedElement` / `logoRunningElement` 三个元素引用。已确认这三个元素没有其他用途；`blockedCount` 等计数变量仍被汇总胶囊使用，保留。
- 三段图形的状态色区分保留，视觉效果变为常亮的三色品牌图形，不再随会话状态明暗变化。

**备注**：常亮后空闲时 logo 也是彩色的，视觉权重略高于现状；若后续觉得抢眼，再单独调整状态色饱和度。

### 2.3 应用图标透明化与放大

**问题**：系统中的应用图标（任务栏 / 开始菜单 / 快捷方式）图形偏小；底部深色背景不符合大多数应用使用透明图标的习惯。

**原因**：`assets/app-icon.svg` 当前铺了一层铺满画布的 `#18181B` 深色圆底，图形 `scale(1.3)` 仅占画布约 70%。深色底是 v1.4 托盘改造时为 16/24px 托盘可读性有意添加的，并非技术限制。

**方案**：

1. 删除 `assets/app-icon.svg` 中的背景圆，背景透明。SVG 为矢量源，`npx tauri icon` 生成时 alpha 通道会保留。
2. 图形 `scale(1.3)` → `scale(1.7)`。按图形包围盒计算，图形占画布比例由约 70% 提升到约 92%，四周留 3~4% 边距，避免 Windows 缩放插值时切边。若实测仍显小，上限约 1.75（边距仅剩 2%），不建议继续增大。
3. 重新执行 `npx tauri icon assets/app-icon.svg`，按约定只保留 `bundle.icon` 引用的 5 个文件；`build.rs` 已声明 `cargo:rerun-if-changed=icons`，重新生成后必须重编才会更新 exe 内嵌图标资源。
4. `index.html` 顶栏内联 SVG 的 transform 同步改为 `scale(1.7)`，保持几何一致；同时把 `.logo` 宽高从 `1.5em` 下调到约 `1.15em`，抵消图形占比变化，顶栏视觉大小与布局维持现状。实测不合适再调整。

**风险与边界**：

- 透明后浅色任务栏上，黄色 `#FAAD14` 内圈波纹对比度会明显下降。2.4 移除圆环 / 角标后不再有状态色兜底；若真机看起来不清楚，退回方案是给图形加自适应描边或局部深色衬底。
- Windows 有图标缓存，重装后开始菜单 / 任务栏可能仍显示旧图标，需要重启资源管理器或卸载重装验证。
- 托盘图标底图来自 exe 内嵌图标，透明化同样生效；状态圆环与右下角角标是叠加绘制，不依赖背景色，合成逻辑无需改动。

### 2.4 托盘状态动画：去掉圆环 / 角标，改为图标自身动效

**问题**：托盘进行中的绿色圆环与告警时的红色圆环 / 角标都叠加在应用图标之上，会遮挡图标主体，和图标本身割裂感明显；告警闪烁只是 Alert / Idle 交替，看起来是「红色图标在跳」，而不是图标自己在动。

**现状**：`build_tray_icon` 在默认窗口图标上逐像素叠加状态色圆环（最细 3px，短边 1/10）与右下角实心角标（短边 24%）；`refresh_tray` 每 600ms 在 Alert / Idle 之间切换一次。

**方案**：托盘三态全部由图标自身动画表达，不再叠加任何图标外元素。

| 状态 | 动画 | 参数 |
| --- | --- | --- |
| 空闲 | 静态 | 单帧，透明底三色图形 |
| 进行中 | 整体透明度呼吸 | 100% ↔ 65%，周期约 1.6s，约 12 帧 |
| 待处理 / 已中断 | 图标缩放弹跳 | 100% → 82% → 100%，周期约 700ms，约 8 帧，不加红色 |

- **不做真正的「滚动」**：会话行底部流光依赖几十到几百像素的宽度与 2px 高光带；托盘实际显示仅 16px（100% DPI）/ 20~24px（高 DPI），中间还经过 32px 源图到系统缩放，旋转弧会重新引入图标外元素，内部高光扫过会被缩放抹平，三色依次点亮更像闪烁。整体呼吸是同等语义下 16px 最清晰可行的替代。
- **不做上下位移**：图标透明化后图形占画布约 92%，边距仅约 1px，位移会裁切；缩放弹跳不需要额外画布空间，也不与 2.3 的「图标放大」冲突。
- **告警形态**：待处理与已中断在托盘上沿用同一弹跳动画（现状也是同一个 Alert 图标），具体类型靠 tooltip 与通知弹窗区分。告警动画只在「窗口隐藏 + 有未读 + 非免打扰」时播放，与现有闪烁逻辑一致；进行中呼吸始终播放，窗口可见时也不停止，不受免打扰影响。

**实现要点**：

1. `TrayIcons` 由三张静态图改为三组预生成帧（`Vec<Image<'static>>`）；删除 `build_tray_icon` 的圆环 / 角标绘制与 `TRAY_RING_*` / `TRAY_BADGE_*` 常量，新增呼吸 alpha 帧与缩放弹跳帧生成函数。缩放帧用双线性采样，避免最近邻锯齿。
2. `TRAY_MONITOR_TICK` 由 200ms 缩短到约 80ms（约 12.5fps），新增动画帧索引推进；`refresh_tray` 的 `last_icon` 改为「状态 + 帧索引」，只在帧变化时 `set_icon`；空闲静止时不写图标。
3. 帧预生成在启动时完成（32×32×4B×约 20 帧 < 100KB）；动画只在 Working / Alert 状态运行，空闲时无额外开销。
4. 免打扰、未读、窗口活跃逻辑沿用现有实现；现有托盘合成测试同步改写，新增帧数、尺寸一致性与 alpha 范围测试。

**分期与降级**：

- 代码保留常量开关 `TRAY_ANIMATION_ENABLED`，动画参数集中为顶部常量，便于快速关闭与调参。
- 第一步只做「去掉圆环 / 角标 + 静态三态」，真机确认托盘图标本身正常；第二步再开启呼吸 / 弹跳动画。
- 若真机上高频 `set_icon` 出现闪烁、图标消失或被安全软件干扰，关闭开关退回静态方案，不需要回滚其它改动。

**风险与验收**：

- **高频 `set_icon` 稳定性是最大未知项**：约 10~15 次/秒调用 `Shell_NotifyIcon` 更新，Windows 10 上一般可行，但可能出现托盘图标短暂重绘 / 闪烁，个别安全软件会干扰，必须真机观察。
- 16px 下呼吸与弹跳的幅度需要真机校准；初始值分别为 65% 与 82%，不够明显时再调整（弹跳可压到 75%）。
- 125% / 150% DPI 下帧间差异会被系统缩放进一步抹平。
- 去掉环 / 角标后托盘不再有静态颜色提示，进行中与告警只能靠动画形态区分；窗口可见时告警动画停止，两者在托盘上无区别，依赖 tooltip。

### 2.5 双击激活：CLI 入口增加 VSCode 窗口兜底，杜绝新建窗口

**问题**：在部分低版本 VSCode 中，从 VSCode 集成终端启动的 CLI 会话双击后无法激活启动它的 VSCode。

**根因**：现有 CLI 链路先沿进程父链找 `Code.exe`，一旦找到就立即 `return focus_vscode_session_window(...)`，失败直接报错，不再尝试 mintty 或其它定位方式。低版本 VSCode 的终端父链结构不同或在中途断开时，可能定位到没有顶层窗口的 `Code.exe --type=utility` 进程，必然失败；另一种情况是主进程找到了但窗口标题匹配不上（工作区标题被改写、打开的是 `.code-workspace`、存在多个窗口），也会直接失败。

**目标**：三种入口的双击效果等价于点击任务栏窗口图标：最小化后恢复、不在顶层时置顶。VSCode 插件会话与 VSCode 集成终端会话均激活 VSCode 窗口，Windows 启动的 Git Bash 会话激活 mintty 窗口。

**方案**：

1. **新增纯窗口激活** `activate_vscode_window_by_directory(directory)`：枚举所有可见顶层窗口，筛选 `Code.exe` / `Code - Insiders.exe`，复用 `vscode_title_score` 按 cwd 各级目录名打分，激活最高分窗口；无命中时若系统中恰好只有一个 VSCode 顶层窗口则激活它；否则失败。全程只做窗口枚举与激活，**不 spawn 任何进程**，从机制上保证不会新建 VSCode 窗口或弹出「打开文件夹」。
2. **CLI 入口改为逐级兜底，不再提前返回**：
   1. 进程祖先定位 → 成功即返回，失败继续
   2. mintty 按 `--cd` 目录匹配
   3. mintty 按终端标题匹配
   4. 全局 VSCode 目录标题匹配（新增兜底）
   5. 系统仅有唯一 VSCode 顶层窗口时直接激活（覆盖标题改写场景）
   6. 全部失败才报错，错误信息说明已尝试的定位方式
3. **插件入口改为只激活不新建**：不再执行 `code <dir>`，改为复用第 1 步的纯激活；找不到已打开的窗口时报错，不新建。同步删除 `open_vscode` 的 spawn 逻辑、`find_vscode_executable`、`reveal_vscode_window` 与 `ELECTRON_RUN_AS_NODE` 处理；非 Windows 平台与 CLI 入口一致，返回「当前平台暂不支持激活窗口」。
4. **不做精确定位到具体 tab / 集成终端**：VSCode 没有公开的「聚焦指定集成终端」命令行接口，Claude Code 扩展的聚焦命令属于内部契约、随版本变化，还需扩展侧配合，成本高且脆弱；激活窗口后由用户自行切换 tab 的体验成本很低。记录为后续可选，不在本版本实现。
5. 前台激活沿用现有 `activate_window`（`IsIconic` → `SW_RESTORE`，`SetForegroundWindow`，`BringWindowToTop` 兜底），本次不加强。

**行为边界**：

- 多个 VSCode 窗口且标题都匹配不上时不动作，避免激活错误窗口；用户会看到错误条提示。
- 任何路径都不新建 VSCode 窗口或 Git Bash 窗口；插件会话所在窗口已关闭时双击只报错。
- Git Bash 会话仍优先匹配 mintty，全局 VSCode 兜底只作为最后手段，避免 Windows 终端会话被错误切到恰好打开该目录的 VSCode。

**风险**：

- 标题匹配依赖 VSCode 窗口标题包含 cwd 的某一级目录名；标题被扩展改写时只能靠「唯一窗口」兜底。
- 「唯一 VSCode 窗口」兜底可能激活与目标目录无关的窗口，但系统中只有这一个 VSCode 窗口，误判成本低。

### 2.6 已完成会话右键「临时隐藏」

**需求**：已完成且确认处理完的会话，既不想去对应窗口点击关闭，也不想继续占用面板。右键提供「临时隐藏」，仅从面板过滤，不修改 `~/.claude/sessions`，不真正关闭会话。

**规则**：

1. 只有状态为「已完成」的行才提供右键菜单，其他状态不响应，避免隐藏需要关注的会话。
2. 隐藏集合仅存前端内存，应用重启后全部恢复显示。
3. 每轮轮询（2 秒）清理隐藏集合：
   - key 已不在本轮 sessions 注册列表 → 清除（`~/.claude/sessions` 中被真正关闭后自动恢复；下次重新打开会话自动显示）
   - 会话 `status` 或 `statusUpdatedAt` 与隐藏时快照不一致 → 清除（状态变化自动恢复）。用时间戳快照而不只看当前状态，是为了覆盖「已完成 → 进行中 → 又回已完成」这种跨轮询的变化。
4. 过滤发生在排序、汇总胶囊、提醒检测与窗口高度计算之前；隐藏行不占空间，也不参与提醒去重。
5. 隐藏期间若状态变为待处理 / 已中断，取消隐藏并按新异常参与提醒：前端 2 秒轮询内恢复，Rust 托盘 5 秒监控同步感知，行为一致。

**交互**：

- 行级 `contextmenu`，仅已完成行响应；菜单为轻量 DOM 弹出层，跟随主题与字号，靠近窗口边缘时翻转位置。
- 点击外部、`Escape`、列表滚动关闭菜单；菜单项「临时隐藏」可键盘聚焦，点击 / Enter 后立即从当前列表移除并收缩窗口高度，不触发后端请求。
- 设置面板「关于」区下方新增「恢复所有临时隐藏」按钮：清空内存中的隐藏集合并重渲染当前数据；没有隐藏项时按钮禁用或给出提示，作为误操作后的手动恢复入口。

**实现要点**：

- 状态判断与过滤抽为 `src/session-state.ts` 纯函数（如 `canHideSession`、`applyHiddenSessions`），Vitest 覆盖四条清理规则。
- `main.ts` 维护最新一轮原始 rows 与隐藏 Map（key → 隐藏时的状态快照）；隐藏后直接用当前数据重渲染，避免额外轮询。
- `settings-panel.ts` 增加 `onRestoreHidden` 回调，由 `main.ts` 接线；按钮文案与提示沿用现有设置面板风格。
- 右键菜单 DOM 与事件留在 `main.ts`，样式复用现有 CSS 变量，不引入框架。
- Rust 侧无需改动：已完成会话不计入托盘进行中 / 告警统计，隐藏不影响托盘与通知。
- 隐私：隐藏集合只存 `pid / cwd / name` 派生的 key 与状态快照，仅内存，不落盘。

**边界与风险**：

- pid 复用：旧会话从 sessions 消失时隐藏记录已清除，新会话即使复用相同 pid 也不会被误隐藏。
- 完成提醒：隐藏行恢复显示时按「新出现」处理，不补发完成提醒；若恢复时是待处理 / 已中断，会正常触发异常提醒。
- 「恢复默认」不清空内存中的隐藏集合；重启应用即全部恢复。

### 2.7 窗口显隐动画：面板缩放淡入淡出

**问题**：窗口显示 / 隐藏都是瞬间切换，托盘左键、全局快捷键、关闭按钮切换时观感生硬，缺少方向感。

**目标**：做出近似「面板被收进托盘」的观感，但不移动窗口本身。

**方案**：

1. 在 `body > #panel` 外新增包裹层 `#panel-stage`，显隐动画只作用于包裹层，避免与 `.panel.is-shaking` / `.panel.is-breathing` 的 `transform` 动画互相覆盖。
2. 动画参数（初始值，实机调整）：
   - 隐藏约 160ms：`scale 1 → 0.65~0.7`、`opacity 1 → 0`，同时向窗口右下偏移 8~14px。
   - 显示约 220ms：反向展开。
   - `transform-origin` 设在窗口右下偏外，让面板朝托盘方向缩小；scale 不宜低于 0.6，否则收缩阶段会被窗口边缘裁掉、像是中途消失。
   - `prefers-reduced-motion: reduce` 时禁用过渡，直接显隐。
3. 入口链路：
   - 关闭按钮：前端先播放退出动画，结束后调用现有 `closeWindow()`；Rust 的 `CloseRequested` 逻辑不改。
   - 托盘左键 / 托盘菜单 / 全局快捷键的隐藏分支：Rust 改为 emit `pinglet://window-hide-request`，前端播放动画；Rust spawn 约 260ms 兜底直接 `hide()`，并用 generation 计数防止「延迟隐藏期间用户又点了显示」被误杀。
   - 所有显示入口继续走 `show_main_window`，复用现有 `pinglet://window-visibility` 事件驱动进入动画；前端记录「收到过 false 后的下一次 true 才播放」，首次启动不播动画。
   - 动画期间暂停 `resizeWindowToContent`，动画结束后补一次；快速连点时用 class / transition 反向打断，不做排队。
4. 窗口显示时第一帧即为收起态：隐藏完成后保留收起状态类，下次 `show()` 后由前端移除并过渡到正常态，避免先闪一帧完整面板。

**不做**：

- **不做窗口位置 / 尺寸动画**，即不做真正飞向托盘图标的位移：会与边缘吸附（`WindowEvent::Moved`）、`tauri-plugin-window-state` 位置存档、自动主题采样、`handleWindowResized` 的尺寸偏好判定、每帧 WebView2 重排同时冲突，补丁版本风险过高。
- 初版 `transform-origin` 固定为右下，不做多显示器 / 任务栏位置的动态计算；实机观感不合适再单独调整。

**风险与边界**：

- 窗口矩形保持不变，动画期间面板外的透明区域仍会拦截点击，最长约 220ms。
- 托盘左键隐藏会多出约 160ms 延迟，Rust 兜底保证前端无响应时仍能隐藏。
- 快速连点显隐时，隐藏延迟任务必须被 generation 取消，否则可能把刚重新显示的窗口再次隐藏。
- 动画期间若发生数据刷新，窗口高度不跟随变化，动画结束后统一收缩一次。

## 三、已讨论但不采纳

- **任务栏显示主窗口图标**：用户实际使用后询问「为什么只有托盘图标、任务栏没有大图标」。现状是原始设计的有意设定（`skipTaskbar: true`，不占任务栏与 Alt-Tab），技术上改为 `false` 即可，但会引入入口重复、透明窗口缩略图空白、Alt-Tab 污染与关闭 / 最小化语义冲突等问题。用户确认托盘小图标已够用，本版本保持现状。
